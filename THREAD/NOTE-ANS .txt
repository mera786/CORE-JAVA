-------------------------------------
Q1. WHAT IS MULTITASKING?
Executing several tasks simultaneously , is concept of multitasking.
Ex- one student can do multiple task at same time:
-> Listening the class
-> Taking running notes.
-> Checking phone
-> Sleeping

Q2. How Many types of MultiTasking ?
There are two types:
 (a) process based : Executing several tasks simultaneously where each task is a separate independently program(process), is called process based multitasking.
Ex-
-> Typing a java program in editor.
-> Listening audio song from same system.
-> Downloading file from net.
Note: process based multitasking is best suitable for OS level.

 (b) thread based: Executing several tasks simultaneously where each task is a separate independent part of the same program , is called thread based multi tasking. And each independent part is called a thread. 
                   Thread based multitasking is best suitable at programmatic level.
Ex-
-> Five thousands line of code and again five thousands line of code in one program running simultaneously.

(B) When compared with old languages developing multithreaded applications in java is very easy because java provides inbuilt support for multithreading with 
    reach API (thread, runnable, thread group).

Q5. How can you create a thread in Java?
A thread can be created in two main ways:
    a.  By extending thread class: 
    --------------------------------
          - You create a subclass of Thread.
          - Override the run() method to define the task.
          - Call start() to execute the thread (not run() directly).
        eg- 
class MyThread extends Thread {
    public void run() {
        System.out.println("Thread is running");
    }
}

public class Main {
    public static void main(String[] args) {
        MyThread t1 = new MyThread();
        t1.start();  // starts the thread
    }
}

    a. By implementing the Runnable interface: 
    ------------------------------------------
          - Implement Runnable and provide the run() method.
          - Pass the Runnable instance to a Thread object and call start().
      eg-
class MyRunnable implements Runnable {
    public void run() {
        System.out.println("Runnable thread running");
    }
}

public class Main {
    public static void main(String[] args) {
        Thread t1 = new Thread(new MyRunnable());
        t1.start();
    }
}

Q2. What’s the difference between start() and run()?
start() method:
 - Belongs to the Thread class.
 - Creates a new thread and then internally calls the run() method.
 - After start() is called, the thread moves to the Runnable state, and the JVM thread scheduler decides when it will execute.
 - Calling start() more than once on the same thread object throws IllegalThreadStateException.

run() method:
 - Defined in Thread or Runnable.
 - If called directly, it does not create a new thread; executes like a normal method in the current thread.
 - Useful when we want to execute the task in the same thread for testing or sequential execution. along with it add this also 

Q3. What will happen if you do overloading of run method ?
  - When you call start(), the JVM creates a new thread and only invokes run() with no arguments. but
  - The overloaded run(int x) will not be called automatically — JVM does not know about it. If you want to execute the overloaded you must call it explicitly like a         normal method.

Q4. What happens if you extend Thread but don’t override run()?
If we don’t override run(), the thread will execute the default run() method in Thread class. If no Runnable was passed, it does nothing. If a Runnable was passed via the constructor, the thread will execute the run() method of that Runnable object.

Q5. What happens if we override the start() method in a Thread class?
If we override start() and don’t call super.start(), no new thread is created. The overridden start() just executes like a normal method in the current thread, and run() will not be invoked unless we call it explicitly. To preserve normal thread behavior, we should call super.start() inside the overridden method.

Q6. If your child class has overridden the start() method, how will you call the parent class’s start()?
Inside the child’s start() method, we can call the parent version using super.start(). This ensures that the original thread creation logic in the parent class is executed and the new thread is started.

Q7. What will happen if you start a thread twice?
A thread can be started only once. If we call start() again on the same thread object, Java throws java.lang.IllegalThreadStateException. To run the thread again, we need to create a new Thread instance and start it.

Q10. What is Thread Schedular ?
(a) it is part of jvm
(b) it is responsible to schedule the thread that is if multiple threads are waiting to get the chance of execution then
    in which order threads will be executed is decided by thread schedular.
(c) We can’t accept exact algorithm followed by thread schedular it is varied from jvm to jvm hence: we can’t expect thread execution order & exact output.

Q11. What is Thread Priority and How many priority present in thread ?
Every thread in java has some priority. It may be default priority generated by jvm or customizer priority provided by programmer. 
The valid range of thread priority is 1 to 10 where 1 is Min priority and 10 is Max priority ,
thread class defines the following common constants to represents some standard priorities:
Thread.MIN_PRIORITY – 1
Thread.NORM_PRIORITY - 5
Thread.MAX_PRIORITY – 10
Thread schedular will use a priority while allocating processor the thread which is having highest priority will get chance first.
If two threads having same priority then we can’t expect exact exultation order it depends on thread schedular.

(a) yield ():
--------------

- Yield () method causes to pause current executing thread to give the chance for waiting thread of same priority if there is no waiting thread or

- If multiple threads are waiting with same priority then which waiting thread will get the chance we can’t expect it’s depends on thread schedular.
- The thread which is yielded , when it will get the chance once again it’s depends on thread schedular and we can’t expect exactly.
Public static native void yield();

Note: some platform won’t provide proper support for yield method.


 (b) sleep ():
--------------
If a thread don’t want to perform any operation for a particular amount of time then we should go for sleep method.
Public static void native sleep(long ms ) throws interruptedException
Public static void native sleep(long ms , int ns ) throws interruptedException
Note: every sleep method throws interrupted exception , which is checked exception hence whenever
     we are using sleep method compulsory we should handle interrupted exception either by try catch or by throws keyword otherwise
     we will get compile time error.



(c) join ():
------------
- if a thread want to wait until completing some other thread then we should go for join method for 
ex- if a thread t1 want to wait until completing t2 then t1 has to call t2.join() 
- If t1 execute t2.join() then immediately t1 will be enter into waiting state until t2 completes 
- Once t2 completes then t1 can continue it’s execution.
ex 2 - Wedding cards printing(t2) has to wait until venue fixing thread(t1) completion hence t2 has to call t1.join()
     - Wedding cards distribution threads( t3) has to wait until weeding cards printing thread(t2) completion hence t3 has to call t2.join()
Public final void join(); // throws interrupted exception
Public final void join( long milisecond); // throws interrupted exception
Public final void join(long millisecond, int nainosecond); // throws interrupted exception
Note: every join method throw interrupted exception which is checked exception hence compulsory we should handle this exception 
      either by using try catch or by throws keyword otherwise we will get compile time error.
