Basics of Multitasking & Threads :
-------------------------------------
Q1. WHAT IS MULTITASKING?
Executing several tasks simultaneously , is concept of multitasking.
Ex- one student can do multiple task at same time:
-> Listening the class
-> Taking running notes.
-> Checking phone
-> Sleeping

Q2. How Many types of MultiTasking ?
There are two types:
 (a) process based : Executing several tasks simultaneously where each task is a separate independently program(process), is called process based multitasking.
Ex-
-> Typing a java program in editor.
-> Listening audio song from same system.
-> Downloading file from net.
Note: process based multitasking is best suitable for OS level.

 (b) thread based: Executing several tasks simultaneously where each task is a separate independent part of the same program , is called thread based multi tasking. And each independent part is called a thread. 
                   Thread based multitasking is best suitable at programmatic level.
Ex-
-> Five thousands line of code and again five thousands line of code in one program running simultaneously.

Q3. What is ADVANTAGE of MultiTasking?
(A) Whether it is process based or thread based the main objective of multitasking is to reduce response time of the system and improve performance.
      The main important applications of area are:
-> To develop multimedia graphic
-> To develop animations
-> To develop video games
-> To develop web servers and application servers etc.
(B) When compared with old languages developing multithreaded applications in java is very easy because java provides inbuilt support for multithreading with 
    reach API (thread, runnable, thread group).

Q5. How can you create a thread in Java?
A thread can be created in two main ways:
    a.  By extending thread class: 
    --------------------------------
          - You create a subclass of Thread.
          - Override the run() method to define the task.
          - Call start() to execute the thread (not run() directly).
        eg- 
class MyThread extends Thread {
    public void run() {
        System.out.println("Thread is running");
    }
}

public class Main {
    public static void main(String[] args) {
        MyThread t1 = new MyThread();
        t1.start();  // starts the thread
    }
}

    a. By implementing the Runnable interface: 
    ------------------------------------------
          - Implement Runnable and provide the run() method.
          - Pass the Runnable instance to a Thread object and call start().
      eg-
class MyRunnable implements Runnable {
    public void run() {
        System.out.println("Runnable thread running");
    }
}

public class Main {
    public static void main(String[] args) {
        Thread t1 = new Thread(new MyRunnable());
        t1.start();
    }
}

Q2. What’s the difference between start() and run()?
start() method:
 - Belongs to the Thread class.
 - Creates a new thread and then internally calls the run() method.
 - After start() is called, the thread moves to the Runnable state, and the JVM thread scheduler decides when it will execute.
 - Calling start() more than once on the same thread object throws IllegalThreadStateException.

run() method:
 - Defined in Thread or Runnable.
 - If called directly, it does not create a new thread; executes like a normal method in the current thread.
 - Useful when we want to execute the task in the same thread for testing or sequential execution. along with it add this also 

Q3. What will happen if you do overloading of run method ?
  - When you call start(), the JVM creates a new thread and only invokes run() with no arguments. but
  - The overloaded run(int x) will not be called automatically — JVM does not know about it. If you want to execute the overloaded you must call it explicitly like a         normal method.

Q4. What happens if you extend Thread but don’t override run()?
If we don’t override run(), the thread will execute the default run() method in Thread class. If no Runnable was passed, it does nothing. If a Runnable was passed via the constructor, the thread will execute the run() method of that Runnable object.

Q5. What happens if we override the start() method in a Thread class?
If we override start() and don’t call super.start(), no new thread is created. The overridden start() just executes like a normal method in the current thread, and run() will not be invoked unless we call it explicitly. To preserve normal thread behavior, we should call super.start() inside the overridden method.

Q6. If your child class has overridden the start() method, how will you call the parent class’s start()?
Inside the child’s start() method, we can call the parent version using super.start(). This ensures that the original thread creation logic in the parent class is executed and the new thread is started.

Q7. What will happen if you start a thread twice?
A thread can be started only once. If we call start() again on the same thread object, Java throws java.lang.IllegalThreadStateException. To run the thread again, we need to create a new Thread instance and start it.

Q13. Explain Difference between Yield(),  Join() and Sleep() ?
Yield(): 
   - If a thread want to pause it’s execution to give the chance for remaining threads of same priority then we should go for yield() method.
Ex :
class MyThread extends Thread {
    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(Thread.currentThread().getName() + " : " + i);
            Thread.yield(); // give chance to other threads
        }
    }
}

public class Test {
    public static void main(String[] args) {
        MyThread t1 = new MyThread();
        MyThread t2 = new MyThread();

        t1.start();
        t2.start();
    }
}


Join():
   - If a thread want to wait until completing some other thread then we should go for join method.
Ex-
class MyThread extends Thread {
    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println("Child Thread: " + i);
        }
    }
}

public class Test {
    public static void main(String[] args) throws Exception {

        MyThread t = new MyThread();
        t.start();

        t.join(); // main thread waits for t to finish

        System.out.println("Main Thread Finished");
    }
}


Sleep():
   - If a thread don’t want to perform any operations for a particular amount of time then we should go for sleep method.
Ex-
class MyThread extends Thread {
    public void run() {
        for (int i = 1; i <= 3; i++) {
            System.out.println("Running: " + i);
            try {
                Thread.sleep(2000); // 2 seconds
            } catch (InterruptedException e) {}
        }
    }
}

public class Test {
    public static void main(String[] args) {
        MyThread t = new MyThread();
        t.start();
    }
}



Q14. How can you interrupt a thread?
 - A thread can interrupt a sleeping thread or waiting thread by using interrupt method of thread class: thread.interrupt()
 - Always check Thread.isInterrupted() inside thread code.
Ex-
class MyThread extends Thread {

    public void run() {
        try {
            for (int i = 1; i <= 5; i++) {
                System.out.println("Running... " + i);
                Thread.sleep(2000); // sleeping
            }
        } catch (InterruptedException e) {
            System.out.println("Thread Interrupted while sleeping!");
        }
    }
}

public class Test {
    public static void main(String[] args) throws Exception {

        MyThread t = new MyThread();
        t.start();

        Thread.sleep(3000); // main thread waits 3 sec
        t.interrupt();      // interrupt child thread
    }
}



Synchronization & Locks :
--------------------------
Q1.  What is synchronized in Java?
A: Ensures that only one thread at a time can execute a block or method. It provides mutual exclusion on the object’s monitor.
Example:
Without synchronized (Problem) :
class Counter {
    int count = 0;

    void increment() {
        count++;
    }
}

public class Test {
    public static void main(String[] args) throws Exception {
        Counter c = new Counter();

        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) c.increment();
        });

        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) c.increment();
        });

        t1.start();
        t2.start();
        t1.join();
        t2.join();

        System.out.println(c.count);
    }
}
❌ Output (Wrong, Race Condition): 1987 (or random)

With synchronized (Correct) :
class Counter {
    int count = 0;

    synchronized void increment() {
        count++;
    }
}



Q2. Difference between synchronized method and synchronized block?
| Aspect | Synchronized Method                            | Synchronized Block                        |
| ------ | ---------------------------------------------- | ----------------------------------------- |
| Scope  | Entire method                                  | Specific portion of code                  |
| Lock   | Locks the object (or class for static methods) | Locks the object specified in parentheses |


Q3. What is the volatile keyword?
Ensures visibility of changes to variables across threads. so that Threads always read the latest value from main memory, not from CPU cache.
Example:
❌ Problem Without volatile (Visibility Issue) :
class MyThread extends Thread {

    boolean stop = false;   // ❌ NOT volatile

    public void run() {
        while (!stop) {
            // do some work
        }
        System.out.println("Thread Stopped");
    }
}

public class Test {
    public static void main(String[] args) throws Exception {
        MyThread t = new MyThread();
        t.start();

        Thread.sleep(2000);
        t.stop = true;   // main thread sets stop flag
    }
}
❌ Problem: Thread may never stop, Because stop value cached ho sakta hai CPU register me, not updated.

✅ Correct Example with volatile :
class MyThread extends Thread {

    volatile boolean stop = false; // ✅ volatile

    public void run() {
        while (!stop) {
            // working
        }
        System.out.println("Thread Stopped");
    }
}

public class Test {
    public static void main(String[] args) throws Exception {
        MyThread t = new MyThread();
        t.start();

        Thread.sleep(2000);
        t.stop = true; // visible immediately to thread
    }
}


Q4. Explain wait(), notify(), and notifyAll() ?
 wait() → Puts thread in waiting state and releases lock.
 notify() → Wakes one waiting thread.
 notifyAll() → Wakes all waiting threads.
Note:- Always call wait() inside a loop to handle spurious wakeups.

Q5. What is a deadlock? How can you prevent it?
   Deadlock → Two or more threads waiting indefinitely for each other’s locks.
   Prevention:
       a. Lock ordering
       b. Use tryLock() with timeout
       c. Minimize lock scope
       d. Avoid nested locks if possible

Java Executor Framework & Thread Pools :
-------------------------------------------

Q1. What is Executor Framework in Java?
It is a high-level API in java.util.concurrent package that simplifies thread management. Instead of manually creating and managing threads, Executor Framework provides a pool of threads to execute tasks asynchronously.

Q2. What is a Thread Pool?
A thread pool is a collection of pre-instantiated threads that are ready to execute tasks. It helps in reusing threads, reduces thread creation overhead, and improves performance.

Q3. What are the main interfaces of Executor Framework?
 - Executor → Executes submitted Runnable tasks.
 - ExecutorService → Extends Executor, adds lifecycle management (shutdown, terminate).
 - ScheduledExecutorService → Executes tasks periodically or after a delay.

Q4. Difference between Executor and ExecutorService?
  - Executor: Only executes Runnable tasks, no lifecycle management.
  - ExecutorService: Executes Runnable & Callable, allows task submission, shutdown, and returns Future.

Q5. How can you create a thread pool in Java?
Using Executors factory methods:
 - ExecutorService fixedPool = Executors.newFixedThreadPool(5);
 - ExecutorService cachedPool = Executors.newCachedThreadPool();
 - ExecutorService singlePool = Executors.newSingleThreadExecutor();
- ScheduledExecutorService scheduledPool = Executors.newScheduledThreadPool(5);

Q6. Difference between FixedThreadPool and CachedThreadPool?
| Feature       | FixedThreadPool     | CachedThreadPool                    |
| ------------- | ------------------- | ----------------------------------- |
| Thread Count  | Fixed number        | Creates threads as needed, can grow |
| Reuse Threads | Yes                 | Yes                                 |
| Suitable For  | CPU-intensive tasks | Short-lived, many tasks             |

Q7. Difference between submit() and execute()?
execute(Runnable r) → No return value, just executes task.
submit(Runnable r / Callable c) → Returns Future for result and exception handling.

Q8. Difference between shutdown() and shutdownNow()?
    - shutdown() → Stops accepting new tasks, waits for submitted tasks to finish.
    - shutdownNow() → Attempts to stop all running tasks and returns a list of pending tasks.

Q9. What are the different thread pool types provided by Executors class?
    - newFixedThreadPool(int n) → fixed number of threads.
    - newCachedThreadPool() → grows/shrinks dynamically.
    - newSingleThreadExecutor() → single worker thread.
    - newScheduledThreadPool(int n) → executes tasks periodically/delayed.

Q10. How does ThreadPoolExecutor decide when to create a new thread?
      - If active threads < corePoolSize → create a new thread.
      - If corePoolSize threads are busy → put task in queue.
      - If queue is full → create up to maximumPoolSize threads.
      - If queue full and maxPoolSize reached → task is rejected.

Q11. Can we dynamically change thread pool size?
Yes, using setCorePoolSize() and setMaximumPoolSize() in ThreadPoolExecutor.
